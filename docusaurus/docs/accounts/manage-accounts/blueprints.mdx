# Blueprints

Blueprints let you configure an account once and reuse that setup everywhere. When a Blueprint is applied, it rolls out AI employees, web chat settings, CRM fields, campaigns, automations, forms, and more to the target account in seconds, without any manual steps.

Blueprints are especially useful for partners onboarding clients at scale, standardizing setup across an industry vertical, or offering SMB self-signup.

:::info
Blueprints were previously called **account templates**. The capability is the same — only the name has changed. You may still see the old name in some places while the rename rolls out.
:::

## What a Blueprint includes

A Blueprint captures the full configuration of a source account, including:

- AI employees
- Web chat widgets and settings
- Forms
- CRM fields
- CRM field layouts
- Campaigns
- Automations

## How to access

To view, create, update, or manually apply Blueprints, go to Partner Center → `Accounts` → `Blueprints`.

The list shows each Blueprint's name, the version currently being deployed, its source account, what it contains, and the date it was created.

<img src={require('./img/blueprints3.png').default} alt="Blueprints list showing each Blueprint's name, applied version, source account, contents, and date created" style={{width: '100%', border: '1px solid #e0e0e0', borderRadius: '8px', boxShadow: '0 2px 8px rgba(0,0,0,0.08)'}} />

## Manually applying a Blueprint

To apply a Blueprint directly to an account, open it from Partner Center → `Accounts` → `Blueprints`, select a target account, choose which components to apply, and click `Apply`.

## Applying Blueprints automatically

### Link a Blueprint to a business category

Link a Blueprint to a business category and any new account created in that category — via API, manually, or through SMB self-signup — automatically gets the matching Blueprint applied. No manual setup required.

### Use the "Apply Blueprint" automation action

Blueprints can also be applied from inside an automation, giving you full control over when and how they are triggered.

To set this up:

1. Go to Partner Center → `Automations`.
2. Select or create an automation.
3. Add the [Apply Blueprint](/automations/my-automations/apply-blueprint) action.
4. Select the Blueprint to apply.

This lets you apply or re-apply a Blueprint based on any condition an automation can evaluate.

## Versions

Every time you save changes to a Blueprint, a new version is created. Versions are numbered in order — `v1`, `v2`, `v3` — and each one records the date it was created, who created it, and what changed.

One version is always the **current version**. That is the version used by every new apply: manual applies, business-category applies, and the `Apply Blueprint` automation action. Accounts that were applied earlier stay on the version they received until you move them.

### Version history

Open a Blueprint and select the `Version history` tab to see the full timeline. Each entry shows:

- The version number and the date it was created
- Who created it, and the description they gave it
- Which components were added and removed compared with the previous version
- How many accounts are currently running that version

Expand a version to see its full configuration, grouped by component type.

### Change the current version

From the `Version history` tab, any version that is not current offers `Change current version to vN`.

This repoints the Blueprint so future applies use the version you chose. It does **not** touch accounts that have already been applied — nothing is deployed and no account changes. Use it to stage a rollout, or to stop a bad version from reaching any more accounts while you remediate.

## Tracking where a Blueprint is deployed

The `Applied accounts` tab lists every account the Blueprint has been applied to, with the version that account is running, its status, and the date it was applied. Summary cards across the top break the rollout down by status and act as filters, and you can search the list by account name.

Each account shows one of these statuses:

| Status | Meaning |
| --- | --- |
| `Up to date` | The account is running the Blueprint's current version. |
| `Out of sync` | The account is running an older version. The row shows the move that is available, for example `v3 → v4`. |
| `Failed` | The last apply did not complete. Expand the row to see which components failed and why. |
| `Applying` | An apply is in progress. |

Accounts running a version newer than the current version are not flagged as out of date, and are not prompted to change.

## Upgrading and rolling back accounts

### A single account

In the `Applied accounts` table, open the `⋮` menu on any row:

- `Upgrade` re-applies a newer version to that account.
- `Roll back this account` re-applies an older version to that account.

Both actions are framed relative to that account's own version, and the row updates to show the new version and status once the apply completes.

:::warning
Applying a Blueprint adds and overwrites — it never removes. Rolling an account back to an earlier version restores that version's components, but components that a later version introduced remain on the account and have to be removed manually.
:::

### Many accounts at once

Select accounts with the checkboxes in the `Applied accounts` table to get a bulk action bar:

- `Reapply to latest version` moves every selected account to the current version.
- `Roll back to version…` moves every selected account to a version you pick.
- `Export errors` downloads one combined CSV covering every failed account in the selection.

Each row updates independently as its account finishes.

## Diagnosing a failed apply

Hover a `Failed` status to see a summary of what went wrong — either the number of components that failed, or a single top-level message when the apply failed before it reached any component.

Expand the row for the per-component breakdown:

| Column | Description |
| --- | --- |
| Object Name | The name of the component that failed |
| Object Type | The kind of component, such as an automation, form, or AI employee |
| Error Stage | The point in the apply where it failed |
| Error Message | The reason the component could not be applied |

To take errors elsewhere, select the affected accounts and click `Export errors`. The CSV contains one row per failed component, with the account, object name, object type, object ID, error stage, and error message. It is generated on demand each time, so there is nothing to expire.

:::info
Error detail is recorded from the point this feature shipped forward. Applies that failed before then do not have per-component detail.
:::

## Including CRM field layouts

A [field layout](/administration/data-management/crm-objects/field-layouts) — the grouping and ordering of fields on contact, company, opportunity, and custom object records — can be rolled out with a Blueprint so every account presents its records the same way.

- Only customized layouts are captured. Object types still on the standard layout are skipped.
- If a layout references custom fields or a custom object type the target account doesn't have, those are created there first and the layout is repointed at them.
- Applying a Blueprint replaces the target account's layout for that object type. Any layout customization already made on the target account is overwritten.

## Including forms and web chat widgets

Forms and web chat widgets configured on the source account can be included in the Blueprint and rolled out to every account it is applied to. This is particularly useful when:

- An initial web chat message needs to be in another language.
- Privacy statements differ by region.

## Updating accounts in bulk

After improving the source account a Blueprint was built from, click `Update Blueprint` to capture the latest changes. No rebuild required. This creates a new version, which becomes the current version for future applies — accounts already applied stay where they are until you upgrade them from the `Applied accounts` tab.

## Using Blueprint application as an automation trigger

When a Blueprint finishes applying, the target account receives an activity log entry. Automations can listen for that entry and chain downstream work off a completed Blueprint application, such as rep assignment or coupon form setup.

## Custom object limits

Each account can have up to 3 [CRM custom objects](/crm/custom-objects). If applying a Blueprint would push a target account past this limit, the application fails for that account and Partner Center shows an error identifying the cause, rather than failing silently.

## Who this is for

- Partners onboarding accounts at scale (enterprise rollouts, reseller channels, migrations)
- Partners standardizing setup across multiple accounts in the same industry vertical
- Partners offering SMB self-signup
