AI Capabilities are specialized skills that define what your AI Employees can do and how they behave when interacting with customers. Think of capabilities as building blocks that transform a basic AI assistant into a skilled employee who can handle specific business tasks.

## What are AI Capabilities?

A **capability** is a discrete skill you can enable or disable for an AI Employee. Each capability contains instructions that guide the AI on:

- Which actions to take in specific situations
- What outcomes to prioritize
- How to respond to different types of requests

Capabilities work together to create AI Employees that can handle complex, multi-step interactions while maintaining consistency with your business processes.

### Types of AI Capabilities

#### Built-in Capabilities
The platform provides pre-configured capabilities for common business functions. Some examples include:

- **Lead Capture**: Automatically collect and qualify lead information (name, email, phone, budget)
- **Appointment Booking**: Schedule meetings using your connected calendar systems
- **Transfer Call**: Live-transfer callers to other numbers based on intent and rules

#### Custom Capabilities
For specialized workflows, you can create your own custom capabilities that:

- Connect to external systems via APIs
- Execute complex business logic
- Integrate with third-party tools and databases
- Automate unique processes specific to your industry

## How Capabilities Work with AI Employees

### Capability Assignment
Each AI Employee can have multiple capabilities enabled simultaneously. The AI intelligently decides which capabilities to use based on customer requests and conversation context.

### Contextual Activation
Your AI Employee evaluates incoming requests and activates the most appropriate capability. For example:
- A question about store hours triggers knowledge base access
- A request for pricing information activates product lookup capabilities
- An interest in services activates lead capture and appointment booking

### Adaptive Behavior
Capabilities can be configured with specific prompts and parameters that modify how the AI behaves. This allows the same capability to work differently across various AI Employees or business contexts.

## Capability Architecture for AI Employees

AI Capabilities are built on a structured architecture that enables flexible, scalable automation. Understanding this architecture helps you design effective capabilities and troubleshoot issues when they arise.

Each capability consists of two main components that work together:

### Prompts
Prompts are written instructions that tell the AI when and how to use a capability. Prompts define:
- Trigger conditions for activation
- Required information before proceeding
- Response templates and tone
- Error handling procedures

### Tools (Custom Capabilities)
For custom capabilities, tools define the technical implementation:
- API endpoints and authentication
- Data parameters and formats
- Integration workflows
- Response processing logic

:::warning
Editing a capability’s Prompt or Tool updates the capability itself and applies to all AI Employees that use it. If you need employee‑specific behavior, prefer using "Additional Instructions" or create a companion capability instead of changing the shared definition.
:::

## Managing Capabilities

Use the Capabilities tab to see all the created capabilities for your AI workforce, edit them, and assign them to your AI Employees. This view is ideal for discovery and management at scale.

- Search at the top to quickly find capabilities by name or description
- Columns include: Capability name, Description, Source (Built‑in or Custom), Assigned Employees, and Last modified
- Click a row to review details or edit a capability
- Use the Create capability button to add a new custom capability (see Creating Custom Capabilities)

### Create a new capability

To create a new custom capability, follow the guide in [Creating Custom Capabilities](./creating-custom-capabilities).
You can start from the global Capabilities tab (Create capability) or from an AI Employee.

## Assign capabilities to an AI Employee

Capabilities can be assigned to an AI Employee by navigating to `AI` › `AI Workforce` and selecting `Configure` on the AI Employee you want to assign capabilities to. This opens a panel where capabilities and other settings specific to that employee are managed.

Clicking on "Add a capability" provides a searchable list of available capabilities. You can select one or multiple capabilities to be added and can be multi‑selected and added in a single action. 

When a use case *isn't* covered by existing options, you can click `New capability` to start building a custom capability (see [Creating Custom Capabilities](./creating-custom-capabilities)). Adding attaches the capability to this employee only; it can be attached to other employees independently.

### Editing prompts and additional instructions
Your custom capabilities and some default capabilities have an editable Prompt field in their details. When available, update the Prompt directly to change default behavior. 

Common modifications include:

- **Trigger conditions** – When the capability should activate (e.g., "Only when customer asks about pricing")
- **Response tone** – How formal or casual the AI should be when using this capability
- **Required information** – What data must be collected before the capability can execute
- **Error handling** – How to respond when the capability fails or returns no results
- **Output formatting** – How to present information back to the customer

 :::tip
 Some default capabilites have a fixed system prompt that is not editable. For these, you may be able to create a new Capability that helps alter the AI Employee's behavior when using the default capability. See [Creating Custom Capabilities](./creating-custom-capabilities) for how to add a companion capability and test your changes often.
:::

## FAQs

<details>
<summary>Where should I put business policies like returns, pricing, or service areas?</summary>

Generally, policies and static information should be added to your [Knowledge Base](../knowledge-base.mdx). If the capability requires real-time data, it should be added to the capability's instructions.

</details>

<details>
<summary>Why didn’t my capability activate during testing?</summary>

Check trigger conditions and required information in the capability’s instructions. Confirm the capability is attached to the employee and enabled. If prompts are locked, add a companion capability to provide additional guidance.

</details>

<details>
<summary>Can I reuse the same capability across multiple AI Employees?</summary>

Yes. You can assign the same capability to multiple AI Employees.
</details>
