# Managing your automations

Once an automation is turned on, use the **Activity** tab on the automation to see each run, diagnose errors, and retry failed runs.

## Automation activity

The Activity tab lists every run of the automation, including errors.

![Automation Activity tab](./img/automations/activity/automation_activity_tab.jpg)

### Activity filters

Filter the activity list to narrow down what you're looking at:

- **Date range** — when the activity occurred
- **Automation** — filter to a specific automation
- **Status** — success, error, in progress, or waiting
- **Business** — filter to a specific business or account

![Automation Activity filters](./img/automations/activity/automation_activity_filters.jpg)

### Activity statuses

Each run shows one of:

- **Success** — the automation completed
- **Error** — the automation hit an error and stopped (see error handling settings in [Creating and configuring automations](./creating-and-configuring-automations.mdx))
- **In progress** — the automation is currently running
- **Waiting** — the automation is paused (for example, waiting for a delay step to finish)

## Error handling

### View errors

Errors appear in the Activity tab with an **Error** status. The row includes a short description of what went wrong.

![Error in activity list](./img/automations/activity/automation_error_handling.jpg)

Click the row to see details:

![Error details](./img/automations/activity/automation_error_display.jpg)

### Retry a failed run

If an automation fails, you can retry the run from any step. Click **Retry** on the failed activity:

![Retry modal](./img/automations/activity/automation_retry_modal.jpg)

Then pick the step to retry from:

![Retry from a specific step](./img/automations/activity/automation_retry_step.jpg)

Use this to fix the underlying issue and resume the run without restarting it from the beginning.
