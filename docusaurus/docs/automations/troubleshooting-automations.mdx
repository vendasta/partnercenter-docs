# Troubleshooting Automations

This comprehensive guide covers common automation issues, their solutions, and best practices for preventing problems before they occur.

## Common Automation Issues

### Why Isn't My Automation Running?

There are several reasons why your automation, or a step in your automation might not be running:

#### 1. Automation is Turned Off

The automation must be turned **On** using the toggle button in the top-right of the automation editor.

![Automation toggle button](./img/automations/faqs/automation-toggle-button.png)

**Solution**: Navigate to your automation and ensure the toggle is set to "On".

#### 2. Entry Settings Configuration

The automation may be configured to run **once per account**, which is the default behavior. To allow the automation to run multiple times per account, update the **Entry settings** in the **Settings** tab of the automation.

**Solution**: 
1. Go to the **Settings** tab of your automation
2. Under **Entry settings**, change from "Run once per account" to "Run every time"
3. Save your changes

#### 3. Automation Encountered an Error

The automation may have encountered an error. Check the **Activity** tab for error messages. If you would like the automation to keep running when an error occurs, update the **Error handling settings** in the **Settings** tab of the automation.

**Solution**:
1. Check the **Activity** tab for specific error messages
2. Fix the underlying issue causing the error
3. Optionally, update **Error handling settings** to "Ignore the error and continue"

#### 4. Trigger Conditions Not Met

The automation may have a trigger condition that doesn't match any accounts. Double-check how your trigger is set up to make sure accounts meet all of the criteria.

**Solution**:
1. Review your trigger conditions carefully
2. Test with a known account that should meet the criteria
3. Simplify conditions if they're too restrictive
4. Use OR conditions instead of AND if appropriate

#### 5. Missing Delay Steps

The automation may have a step that only makes sense after a delay occurs, but no delay was provided. For example, you may build automation that starts with a trigger of an account being created, and then an if/else branch based on the salesperson assigned to the account. In this case, it takes about 10 minutes to assign a salesperson to an account once the account is created. Since that delay is not accounted for in the automation, the automation will stop running when it gets to the if/else branch.

**Solution**:
1. Add appropriate delay steps before conditions that depend on other processes
2. Use "Delay Until" steps for event-based delays
3. Add simple time delays (e.g., 10-15 minutes) for system processes

#### 6. Step Limitations

The automation may have a step that can only run once per account under any circumstance, which can't be changed. For example, an email campaign can only be sent **once** to the same account. If you build automation that involves sending a campaign to an account, and you want the automation to run multiple times per account, the automation will have errors since it can't send the campaign multiple times.

**Solution**:
1. Understand which steps have "once per account" limitations
2. Design workflows that account for these limitations
3. Use different campaigns for repeat communications
4. Consider using pause/resume campaign steps instead

## Email Campaign Issues

### Campaign Failed to Start

When attempting to start an email campaign from Automations, you may encounter an error stating: "Failed to complete due to an error. The required contact information for campaigns is missing."

![Campaign Failed Error](./img/automations/faqs/campaign-failed-error.png)

This error occurs when there is no contact information specified in Partner Center for your business. You must include your contact information within every promotional email campaign, including a physical mailing address or PO Box where you can receive mail.

#### Solution: Add Required Contact Information

To fix this error, you'll have to enter your contact information in Partner Center:

1. Go to **Partner Center** > **Administration** > [**Customize**](https://partners.vendasta.com/customize-design)
2. Expand the **Email Settings** tab
3. In the **Required Contact Information for Campaigns** section, fill in the required fields
4. Click **Apply Changes** to save your settings

:::note Market-Specific Settings
If you have Markets enabled, make sure that each market has the required contact information. To access the email settings for each market, click on the **Markets** tab at the top of the **Customize** page, then click the **Edit** icon for a specific market. For each market, you can choose to use the **Partner's Contact Information** or **Market's Contact Information**. However, selecting **None** will disable campaigns from being sent in that market.
:::

:::warning Default Market Requirements
Even if it is a default market, this setting is necessary in order to get the campaigns completed successfully.
:::

![Market Contact Settings](./img/automations/faqs/market-contact-settings.png)

### Other Campaign Issues

**Campaign Not Sending**
- Verify the campaign is published and active
- Check that the account has users with valid email addresses
- Ensure the campaign hasn't already been sent to the account

**Campaign Sending to Wrong Audience**
- Review your trigger conditions
- Check list membership if using list-based triggers
- Verify account segmentation is correct

## Account Management Issues

### Can I Remove an Account from an Automation?

Once an account has been processed through automation, it cannot be undone. However, if the automation includes a delay step, you may have a brief window of time to intervene and stop the process. If no delay step is present, the automation will complete almost instantly, leaving no opportunity to interrupt it.

#### Prevention Strategies

1. **Use Test Accounts**: Always test automations with test accounts first
2. **Add Confirmation Steps**: Include manual approval steps for critical actions
3. **Use Staging Environments**: Test in a separate environment before production
4. **Implement Safeguards**: Add conditions to prevent automation on certain account types

#### What You Can Do

**If the automation is still running:**
1. Go to the **Activity** tab
2. Look for "In Progress" or "Waiting" status
3. If found, you may be able to cancel the remaining steps

**If the automation has completed:**
1. Manually reverse any actions that can be undone
2. Update account records to reflect the correct state
3. Add the account to exclusion lists to prevent future issues

## Data and Integration Issues

### API and Webhook Problems

**API Automation Not Triggering**
1. Verify API credentials are correct
2. Check API endpoint URLs
3. Review payload format and required fields
4. Test API calls manually first

**Webhook Issues**
1. Confirm webhook URL is accessible
2. Check webhook payload format
3. Verify authentication if required
4. Test webhook endpoint independently

### CRM Integration Issues

**Contact/Company Creation Failures**
1. Verify required fields are populated
2. Check for duplicate prevention rules
3. Ensure proper permissions are set
4. Review field mapping configuration

**Opportunity Management Problems**
1. Confirm pipeline stages exist
2. Check opportunity association rules
3. Verify user permissions for opportunity creation
4. Review field validation requirements

## Performance and Timing Issues

### Automation Running Too Slowly

**Causes and Solutions:**

1. **Too Many Simultaneous Runs**
   - Stagger automation triggers
   - Use delay steps to spread load
   - Consider rate limiting

2. **Complex Conditions**
   - Simplify trigger conditions
   - Reduce the number of conditional branches
   - Optimize filter logic

3. **External API Delays**
   - Add appropriate timeout settings
   - Implement retry logic
   - Consider asynchronous processing

### Timing-Related Issues

**Steps Executing Out of Order**
1. Add explicit delay steps between dependent actions
2. Use "Delay Until" steps for event-based sequencing
3. Review automation flow logic

**Race Conditions**
1. Identify competing automations
2. Add coordination mechanisms
3. Use exclusive locks where necessary

## Diagnostic Tools and Techniques

### Using the Activity Tab

The Activity tab is your primary diagnostic tool:

1. **Filter by Status**: Focus on "Error" status entries
2. **Review Error Messages**: Look for specific error details
3. **Check Timing**: Identify when issues occurred
4. **Track Progress**: Monitor "In Progress" automations

### Testing Strategies

**Systematic Testing Approach:**

1. **Unit Testing**: Test individual steps in isolation
2. **Integration Testing**: Test complete workflows end-to-end
3. **Load Testing**: Test with multiple simultaneous triggers
4. **Edge Case Testing**: Test with unusual or boundary conditions

**Test Account Strategy:**
1. Create dedicated test accounts
2. Use test data that mirrors production
3. Test all possible trigger scenarios
4. Verify cleanup procedures work correctly

### Monitoring and Alerting

**Set Up Proactive Monitoring:**

1. **Error Notifications**: Configure alerts for automation failures
2. **Performance Monitoring**: Track execution times and success rates
3. **Regular Reviews**: Schedule periodic automation health checks
4. **Capacity Planning**: Monitor system resource usage

## Prevention Best Practices

### Design Phase

1. **Plan Thoroughly**: Map out complete workflows before implementation
2. **Consider Edge Cases**: Think about unusual scenarios
3. **Design for Failure**: Plan how to handle errors gracefully
4. **Keep It Simple**: Start with simple automations and add complexity gradually

### Implementation Phase

1. **Test Extensively**: Test all scenarios before going live
2. **Use Staging**: Implement in a test environment first
3. **Gradual Rollout**: Start with a small subset of accounts
4. **Monitor Closely**: Watch for issues during initial deployment

### Maintenance Phase

1. **Regular Reviews**: Periodically review automation performance
2. **Update Conditions**: Keep trigger conditions current with business changes
3. **Clean Up**: Remove or update obsolete automations
4. **Document Changes**: Keep records of modifications and their reasons
