## Project Overview

This is the Partner Center documentation site for Vendasta, built with **Docusaurus 3.8.1**. The site is published at `https://docs.vendasta.com`.

## Development Commands

All commands run from the `docusaurus/` directory:

```bash
cd docusaurus
npm install          # Install dependencies
npm run start        # Local dev server at http://localhost:3000
npm run build        # Generate static site to build/
npm run typecheck    # TypeScript type checking
npm run clear        # Clear Docusaurus cache
npm run serve        # Serve built site locally
```

Node.js >= 18.0 required.

## Architecture

### Content Structure

- **All documentation lives in `docusaurus/docs/`** organized by product area
- Uses **file-system based autogenerated sidebars** - folder structure determines navigation
- Each folder can have `_category_.json` to customize label, position, and collapse state
- Landing pages use `index.mdx` files within their category folder

### Key Configuration Files

| File | Purpose |
|------|---------|
| `docusaurus/docusaurus.config.ts` | Main site config, redirects, plugins |
| `docusaurus/sidebars.ts` | Sidebar configuration (uses autogenerated) |
| `docusaurus/src/components/` | Custom React components (Cards, PageActions, Icons) |
| `docusaurus/src/theme/` | Theme overrides (MDXComponents, TOC, Root) |

### Redirects

URL redirects are managed in `docusaurus.config.ts` via `@docusaurus/plugin-client-redirects`. When moving or renaming pages, add a redirect to preserve links:

```ts
{ from: '/old/path', to: '/new/path' }
```

## Content Guidelines

### Voice & Tone

- **Fun, not silly** | **Professional, not formal** | **Helpful, not overbearing** | **Expert, not bossy**
- Active voice: "Admins can change these settings"
- Present tense: "View your invoices"
- Avoid internal jargon in Partner-facing docs

### Markdown Rules

- **CRITICAL: Never use `>` character in markdown** - creates unintended blockquotes. Use "greater than" in text or `→` for UI paths
- Use Docusaurus callouts: `:::tip` (green, best practices), `:::info` (blue, extra info), `:::warning` (yellow, cautions)
- Sentence case headings: `## Set up a domain`
- Heading hierarchy: `##` for sections, `###` for subsections
- **Bold** for UI elements, *italics* for foreign words only, `code` for commands and filenames
- Numbered lists for sequences, bullets for options
- Navigation paths: `**Partner Center** > **Accounts** > **Manage Accounts**`

### Frontmatter

```yaml
---
id: file-name
title: Page title
sidebar_position: 1
description: Short description
---
```

### Category Configuration

Use `_category_.json` in folders to customize sidebar:
```json
{
  "label": "Display Name",
  "position": 5,
  "collapsed": true,
  "link": { "type": "doc", "id": "folder/index" }
}
```

Link categories to actual overview documents - avoid generated-index pages.

### Details/Summary Formatting

Place `<details>` tags on own lines with blank lines around content:
```markdown
<details>
<summary>Title</summary>

Content here with blank line above.

</details>
```

### Media

- **Images go in an `img/` folder alongside the documentation files** (not in `static/img/`)
- Use Docusaurus `<img>` tags with `require()` instead of plain markdown `![]()`
- Standard style on every image: `border: '1px solid #e0e0e0'`, `borderRadius: '8px'`, `boxShadow: '0 2px 8px rgba(0,0,0,0.08)'`
- Always set `width` explicitly (`'100%'` for full-page screenshots, smaller for partial UI)
- Example structure:
  ```
  docs/section/feature/
  ├── index.mdx
  ├── settings.mdx
  └── img/
      ├── settings-screenshot.png
      └── feature-diagram.png
  ```
- Example usage:
  ```jsx
  <img src={require('./img/image-name.png').default} alt="Description" style={{width: '100%', border: '1px solid #e0e0e0', borderRadius: '8px', boxShadow: '0 2px 8px rgba(0,0,0,0.08)'}} />
  ```
- Always include alt text describing image purpose
- Blur or replace sensitive data (PII) in screenshots

### Naming Conventions

- **Directories**: lowercase kebab-case, no spaces (e.g., `getting-started/`, `vendor-center/`)
- **Git branches**: lowercase kebab-case (e.g., `feature/add-new-section`, `fix/update-links`)

### Product & UI Naming

- Capitalize branded products: Vendasta Payments, Marketplace
- Lowercase generic objects: accounts, invoices
- Match UI labels exactly
- Material UI terms: hamburger menu, kebab menu

### Linking

- Internal links: `[Text](./file-name.md)` (relative path)
- External links: `[Text](https://example.com)`
- Avoid "click here" — use descriptive link text
- Check all links before committing

### Grammar & Mechanics

- Acronyms: spell out on first use — Google Business Profile (GBP)
- Numbers: numerals for 10+, spell out 1–9
- Dates: October 15, 2025
- Time: 3:00 pm–4:00 pm
- Units: 20 GB
- File extensions: PDF, CSV
